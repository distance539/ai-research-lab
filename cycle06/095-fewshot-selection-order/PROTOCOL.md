# Frozen experiment protocol: 2026-10-08

Question: how do two fixed demonstration sets and their order affect predictions on the same 64 development questions? A descriptive, within-question comparison; not a full benchmark or a confirmatory test. No claim that few-shot must lose.

Reuse article094's original SmolLM2-135M-Instruct, pinned model/tokenizer and GLUE SST2 resources.lock.json, harness0.4.9.2 and task YAML. CPU float32, eager attention, four threads, seed95, batch1, max512. No chat template, BOS, EOS, generation, training, calibration, length normalization or result-based selection. Scores sum candidate-token log probabilities; ties choose negative. Refuse truncation.

Demonstrations use the official train split only. Normalize whitespace/case and exclude any exact text match to all validation questions and within/across demo sets. This overlap screen does not use validation labels. Sort training rows by SHA256('95:'+idx). Require each formatted demo block to have exactly42 tokens, including answer and double-newline delimiter. Take the first4 eligible negatives and first4 positives; A uses first2 of each, B next2 of each, interleaved negative/positive/negative/positive. No model scores are used to select demonstrations. These short, balanced sets are not a representative random sample of the entire train distribution.

Conditions frozen: zero, A_forward, A_reverse, B_forward, B_reverse. Reverse changes the order of the same four examples, not labels or content. Each few-shot prefix must have identical actual token length; each evaluation question must have identical context length across all four few-shot conditions. Zero-shot necessarily has a different input budget; do not call that an equal-compute causal estimate of sample count. Log all candidate input tokens and elapsed time.

Evaluation IDs: the first64 validation rows sorted by SHA256('88:'+idx), as in094. Next128 SST2 confirmation examples, plus previously reserved64 AGNews examples, are never inferred. Keep rows paired; do not treat320 outputs as320 independent test examples. Frozen plan saved before target inference. Smoke: first2 dev rows across all5 conditions, no settings selected from smoke accuracy. Full run: all64 across all5 conditions. Resource gate after smoke: conservative2x linear extrapolation <=600s and RSS<4GiB. No post-result grid expansion or early stopping for scores.

For each condition use the official ContextSampler subclass with only sample(n) overridden to return the fixed ordered train rows. Task context formatting, official simple_evaluate, HFLM likelihood and metric implementations unchanged; custom_dataset changes transport only. Independently construct each prompt and assert equality; run direct Transformers score calculation on every row/candidate, compare official likelihood within2e-5. Store raw dataset/prompt traces privately, distribute derived scores, identities, indices and metadata only.

Primary descriptive endpoints: accuracy per condition, correct-to-wrong and wrong-to-correct counts, prediction flips, and paired mean correctness difference. Predeclare contrasts: all four few-shot conditions vs zero, A_reverse vs A_forward, B_reverse vs B_forward, B_forward vs A_forward, B_reverse vs A_reverse. Exact denominator64. No confidence intervals/p-values or claims of best universal order: only two sets/two orders, one small model and repeatedly used development data.
