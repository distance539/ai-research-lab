# Preregistered protocol — 2026-10-09

Question: Does changing the displayed order or the scored answer space change semantic predictions of the same frozen model on the same 64 SST-2 development items?

Inherited model/tokenizer/data revisions and development/reserved IDs are fixed in resources.lock.json and plan.json, from 095 commit 2522a45e1d2efbb2ff1692be4fc734627ea00b55. No fine-tuning, examples, calibration, generation, chat template, BOS, EOS scoring, truncation, or inference-cache reuse. The 128 reserved SST-2 and 64 reserved news items are not inferred. Development has already been inspected in previous articles; no blind-test claim.

Five conditions, all reported: official_text (original official SST-2 context and negative/positive candidates); listed_text_forward/reverse (add A/B option lines, score option contents); listed_letter_forward/reverse (IDENTICAL listed contexts, score A/B). Forward semantic mapping [0,1], reverse [1,0]. Gold position is mapping.index(original gold), and every predicted position is mapped back to original semantic ID before pairing. A and B remain in displayed positions; reversing contents changes their semantic binding. This does not isolate physical position from symbol identity. No answer-style instruction is added: text-vs-letter estimates two restricted answer spaces under an identical prompt, not instruction compliance or free-generation accuracy.

Primary endpoint: per-question semantic prediction flips and gains/losses under forward/reverse for each answer space, using summed conditional log likelihood. Secondary: cross-space disagreements at each order, accuracy and semantic-positive/first-position counts. Report all five conditions; choose no winner. Each has two candidates per item (640 candidate likelihoods total), independently and officially scored. Equal candidate count does NOT imply equal token work; measure context/continuation lengths, padding-free input token totals and timings. No pooled 320-row confidence interval.

Normalization: replay identical likelihoods with sum, mean per continuation token, and mean per choice character. The harness acc_norm divides by characters, excluding separator space; independent token mean divides by actual scored continuation token count (including its leading space tokenization). If denominators are equal, report algebraic invariance; do not claim normalization is generally harmless or invent unequal-length alternatives after looking at results.

Independent score path: full concatenated tokenization with exact context-prefix assertion, shifted logits and per-token log-softmax. Official path: HFLM.loglikelihood and ConfigurableTask.process_results(acc,acc_norm), using custom local fixed GLUE data. Compare all candidate sums within 2e-5. Argmax uses first maximum. Save per-token values/IDs, score parity, shapes, original gold/mapping/gold position, context and source hashes. Do not distribute full reviews, prompt text or input token IDs; public continuation IDs are only labels.

Before full inference run two development items through every condition. Full-run projection = fixed setup + twice 32 times smoke scoring time; maximum 1200 s and 4 GiB peak RSS. Preserve failures and any budget amendment. Timing excludes imports and resource download, which are separately logged. CPU float32/eager/4 threads, seed96. No GPU-memory claim.

Independent arithmetic audit checks identities, sum, normalization, argmax, labels, official agreement and paired counts across all saved rows. This is automated recomputation, not human semantic review. Deterministic permutation preserves original data labels; no new manual gold is asserted.
